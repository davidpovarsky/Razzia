# Phase 2 native product QA

Run every build, browser, runtime and lint command on the Tadazz server in the isolated `tadazz-phase2-20261116` container. The owner's workstation is for source edits, Git inspection, transport and reading server-generated artifacts only.

This suite imports read-only approved Goldy source into disposable private QA accounts. It never writes to the mounted source account. Its explicitly derived test shows exercise original question content, owned placeholder bytes, original Razzia/Classic renderers, existing media and Creating Worlds choreography. Fixture participants are synthetic. The owner also authorized the existing goldysterling games for preview. One text-only sanitized derivative of Example Quizz is bound to the public quiz card through the explicit, OFF-by-default TADAZZ_PUBLIC_GAME_PREVIEW_ENABLED flag. It exposes no tenant IDs, media, notes, roster or account grants. Other illustrative catalogue entries remain unavailable until a suitable source is approved and bound. Public source and native-runtime requests require no account authorization; the existing homepage may independently create its ordinary guest player session.

The native preview build is an application build artifact, distinct from portable uploaded code approval. `node extensions/qa/build-application-preview.mjs` builds the actual original presentation components, rejects live room contexts, hashes code/styles/source/toolchain/native resources, and writes derived build metadata. The checked-in metadata is unavailable until that build succeeds. Never substitute a hand-written compiled pin. Build extensions before the web/socket application so both consume the same metadata. The site build copies the verified runtime into `web/tadazz-application-runtime` for the packaged server.

Use `TADAZZ_REMOTE_QA=1` with `product.config.ts`; the browser config rejects an omitted remote QA marker. API and website bind isolated container loopback, without published ports or an external tunnel. The account fixture enables author/publish only for disposable fixture accounts; product grants stay explicit. The production/customer database, phone gateway, metadata keeper, provider settings and public installer are outside this test environment.

`product.spec.ts` checks actual rendered/decoded content, authoring persistence and immutable publication, source/asset/account failures, all audio event policies, mixed media clocks, original editor drag/duplicate, both renderer families, eight locales, responsive/reduced-motion behavior, long-press/cancel/click rules, rapid seek and repeated cleanup. Chromium CDP measurements are controlled laboratory observations, not field Core Web Vitals. Linux WebKit is not a physical Safari/iPad certification.

Keep source manifests, failed results, successful results and artifact SHA-256 receipts. Private projections and raw traces stay on the server. Download only sanitized result summaries and screenshots needed for review. Final acceptance must identify one committed source HEAD and its derived artifact receipt; earlier partial runs are supporting evidence only.

The public marketing demo and its entry points use that same native Preview surface; the former illustrative voting implementation has been removed. An optional show-brand image is selected from the existing account Media Library, independently of the platform mark. Immutable saved theme references block physical media deletion, including forced detach and archived versions. Guest room media access is restricted to the audience projection of the admitted composition.
