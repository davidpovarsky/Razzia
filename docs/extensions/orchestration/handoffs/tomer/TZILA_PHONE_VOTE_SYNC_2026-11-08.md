# Urgent persistent-call vote synchronization repair

Owner reported three connected callers pressing answers but no votes appearing on repeated questions. Read-only gateway history contains inactive/duplicate callbacks. Reproduced the deterministic gateway defect with three persistent provider call sessions: Q1 accepts3 votes; without a30-second timeout poll between questions, Q2 accepts0/3 because the cached prompt epoch from Q1 is submitted to Q2. Backend correctly rejects this stale epoch. Previous one-question gateway checks and multi-question direct-backend checks did not cover this case.

Minimal gateway-only fix: refresh session question/answered state from the authoritative poll before processing the arriving digit, submit that fresh poll's epoch, and retain the backend epoch race check between poll and submission. Generic long-lived keypad reads span questions and cannot be treated as question-specific prompts. Room-change rejection and per-question duplicate protection remain. Added privacy-preserving answer diagnostics: public dialed channel, one-way hashed call identifier, question index/epoch, acceptance/rejection reason/status; no phone numbers, route secret, token or answer choice logged.

Native Node regression uses real HTTP callbacks through the gateway with a controlled authoritative backend,3 persistent callers across10 questions, first presses only, duplicate attempts and closed voting.
