## Contract and acceptance

- Trusted server catalog maps price ID to immutable plan version/currency.
- Manager claims determine tenant; checkout callbacks never grant access.
- Raw-body HMAC, five-second timestamp tolerance, durable dedupe by event ID;
  transactional effects and retry/reconciliation for unordered events.
- Separate billing SQLite database, WAL, transaction-based quotas; no card data.
- One-off game credits and recurring period grants, participant caps, game count,
  live upgrade, payment-failure grace, cancel/renew/refund mirrors.
- Stable roster/client identity counts once, reconnect does not consume again;
  connected count remains distinct. Phone minute usage is a separate meter.
- New UI composes original Button/Card/Input/Select/AlertDialog, inherits theme
  and Rubik. No feature stylesheet or new UI primitives.
- Unit/integration/real HTTP/Socket.IO and browser tests, complete locale keys,
  restart and security cases. Actual Paddle sandbox E2E remains pending account.

## Implemented boundaries and integration notes

All feature logic lives in small `extensions/src/{core,server,editor}/billing`
modules. Host-only adapters bind existing session auth, React Query, Razzia
primitives and process configuration. No dependency or global style was added.
The generated `packages/web/src/route.gen.ts` contains the new thin
`/manager/checkout` route and must be regenerated together with any concurrent
theme routes during integration.

Protected Game hooks are limited to reservation after ID creation, admission at
the actual new-player boundary (stable roster/client identity), simulated-phone
admission/poll/hangup and spending a credit immediately before the real round
starts, after player validation. Opening animations do not spend a credit.
When the concurrent cleanup moves phone logic out of Game, preserve these guards
in its extracted controller instead of duplicating them. No scoring, accepted
answer, timer or animation logic was moved into billing.

The two baseline compatibility corrections are isolated from billing. Full test
execution regenerates the historical native-scenes HTML harness; that unrelated
generated fixture was restored byte-for-byte to its committed baseline.

Local lint exceptions are narrowly documented at explicit multi-coordinate
adapter signatures, ordered browser/provider loops and the Paddle/TanStack APIs.
No safety/type rule was disabled globally. Largest new product module: 247 lines.
