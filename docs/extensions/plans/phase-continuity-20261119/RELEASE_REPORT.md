## Defect and resulting behavior

The defect existed in project rendering and MCP integration code. It was not evidence of a ChatGPT transport malfunction.

1. The MCP widget keyed its native child by selected chapter and phase-clock epoch, remounting a question as answers/results appeared. The redundant phase key was removed; the parent still resets for a new question, revision or explicit Replay.
2. Razzia used phase epoch and result visibility in question/answer entrance identity, and switched existing text cards to another entrance preset at results. Continuous playback now owns entrances by question identity; selection, correctness, counts and percentages update existing content. Cold snapshots retain their independent entrance behavior.
3. The shared V4 adapter did not communicate that a question was already visible, and the scene root used animation revision as its React key. Explicit continuity now preserves the same nonempty question within the supported question composition. Newly introduced answers can enter without replaying the question. Different questions, cold compositions and Replay still receive fresh entrances.
4. Paused forward transitions reconstructed a cold scene and hid the entire surface. Same-question forward updates now retain the visible stage and respect the latest paused state. Explicit backward navigation reconstructs the requested earlier phase so later answers/results cannot remain stale.

Photo-question continuation preserves the readable question while introducing new artwork/options. Positive-vote photo results retain their authored winner/runner composition and legitimate result animation; zero-vote results preserve the existing grid entrance. `PhotoCardGrid` itself was not redesigned. Result labels, highlighting and ranking remain part of the native composition. See [shared source analysis](shared/source-analysis.md).
