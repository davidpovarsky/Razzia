## Retained controller documentation

The remainder documents the original `run-source-qa.py` / `remote-source-qa.py` contract for reproducibility. Earlier revision/cache examples below are historical, not current release inputs. The release owner supplies the exact reviewed manifest and current helper/service pins for each run. These source-check controllers do not deploy, use customer mounts or run an application on Windows.

## Files

- `run-source-qa.py`: packages the exact committed source plus explicitly approved worktree files, sends the immutable snapshot to the Linux server, retrieves evidence, and copies back only verified Prettier output.
- `remote-source-qa.py`: companion sent through SSH by the first script; never invoke it on its own.
- The reviewed input manifest is supplied by the release owner after all source changes are frozen. A draft manifest is intentionally not supplied as an approval.

## Input manifest

Use a JSON object with these required fields:

| Field           | Value                                                                                                                                                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseRevision`  | Exact 40-character committed Git HEAD for that reviewed snapshot. The earlier `0c0846f06b1249d9ac2b51df4a21f9c614b211ce` example is historical and is not the current candidate.                                       |
| `approvedFiles` | Object mapping exact repository-relative POSIX paths to SHA-256 hashes of the approved worktree bytes. This is the complete delta; unrelated local edits are excluded.                                                 |
| `formatPaths`   | Explicit, unique subset of `approvedFiles` for Prettier. Only these paths may be copied back.                                                                                                                          |
| `vitestSuites`  | Explicit, unique list of meaningful `.test.ts` suites in `extensions/src/` or `packages/`, present in the snapshot.                                                                                                    |
| `baseSourceRun` | Canonical source cache run for the reviewed snapshot. The retained controller default, `tadazz-codex-845b2ae6cba5-330e1375`, is historical; the current owner-supplied manifest must identify the intended source run. |

The snapshot includes the committed files in the canonical source manifest, all committed `extensions/` and `packages/` files, and root build/test/format configuration including `vitest.config.ts`. Committed source bytes are read from Git blobs, not from the worktree. The approved delta then replaces only the named files. Each byte stream has a manifest hash. The canonical base cache must still match its original complete manifest.

The local controller performs only source packaging, hashing, SSH transport, evidence collection, and guarded formatter copy-back. The release owner may invoke it after review with Python and `--manifest <absolute-path-to-reviewed-manifest.json>`. Run it as a tracked job, and keep progress communication available while it works.

## Linux execution boundaries

The remote controller uses the existing SSH host, network-isolated dependency cache, and dependency mounts from `run-mobile-wip.py`. It creates one uniquely named container:

`tadazz-codex-experience-qa-<HEAD12>-<random8>`

The container has network disabled, a read-only root filesystem, 2 GiB RAM/swap limit, one CPU placed on CPU 1, bounded PIDs, and temporary scratch space. Only the owned source/evidence directory is writable. Existing dependency mounts are read-only. No customer configuration, media, data, or production mount is supplied.

Before and after every command, the controller checks that no other heavy QA/release container is active, the deployment lease is free, no stage/deploy controller is running, and production and dependency-cache identities are unchanged. It stops only its own verified container during cleanup. Cleanup still runs if a guard fails.

Execution is bounded to 2100 seconds overall, with a server timeout and container lifetime. Each command also has its own timeout:

1. Prettier writes only the approved `formatPaths` (120 seconds).
2. Extension TypeScript checks (240 seconds).
3. Web TypeScript checks, with build-info output in `/tmp` (240 seconds).
4. Requested extension Vitest suites with the extension config (600 seconds).
5. Requested workspace Vitest suites with the root projects config (600 seconds).

Both Vitest groups run serial files with a single worker/concurrent test limit. Normal nonzero check exits are recorded and do not skip later independent checks. A transport timeout or failed guard stops further work. The original source cache must remain unchanged, and tests/type checks may not alter snapshotted source bytes.

## Evidence and formatter copy-back

The per-run directory records approved input bytes, exact source manifests, remote controller bytes, every command's output/error/exit code, guard exceptions, complete receipts, and returned artifacts. Local exceptions and partial copy-back progress are retained. A failing check remains a failing controller result.

Formatter output is returned only after Prettier exits successfully and only for paths that actually changed. The local controller validates every returned path and SHA-256 hash. Before copying anything back, it rechecks HEAD and **all** approved input hashes; a concurrent edit prevents copy-back. It rechecks each target immediately before the atomic file replacement as well. Type-check or test failures are never replaced by a formatting success.

This controller does not run the browser acceptance helpers. The separate disposable server harness retains the original eight native editor/vote checks and the imported guest, platform, editor-refinement and viewer/control assertions. Current acceptance also requires the supplementary package-presentation gate. The completed reports determine the actual counts; no planned assertion count is a pass. No helper should be skipped by default.
