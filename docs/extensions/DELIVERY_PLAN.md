# Sequenced implementation plan — planning only

Phase 0: baseline + protected-upstream guard + extension bootstrap. Acceptance: clean upstream diff, reproducible install/test/build, proof of optional module registration. No feature implementation before approval.
Phase 1: shared contracts, versioned metadata, i18next namespace loading and editor slots; owner approves each tiny upstream hook before changes.
Phase 2: leaderboard cadence and team scoring with old-game regression tests.
Phase 3: image answers, reveal effects and synchronized presenter/player views.
Phase 4: interludes, audio cue customization and editor preview; state persistence and reconnect tests.
Phase 5: provider-neutral telephony bridge, Yemot capability proof, UK dialability and DTMF event tests; add Telnyx adapter only if needed.
Phase 6: end-to-end accessibility, privacy/security, load tests, upgrade rehearsal from upstream/main and release candidate.
Every phase: RFC/acceptance criteria -> isolated worktree -> implementation -> independent QA -> upstream drift report -> owner approval.
Do not interpret this sequence as permission to start coding or to buy phone numbers.
