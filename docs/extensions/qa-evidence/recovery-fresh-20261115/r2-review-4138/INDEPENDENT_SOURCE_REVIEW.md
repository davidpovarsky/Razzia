## Findings

1. **P1 — Native quiz-save replay accepts a vanished sidecar.** In `extensions/src/server/storage/native-recovery-adapter.ts:113–130`, admission compares a present sidecar to the complete backup and target, then admits a missing sidecar unconditionally. For an update with non-null backup and target extras, absence matches neither state. With the base at the journal target, `storage/journal.ts:346–380` can restore the base, recreate the sidecar and ultimately remove the journal at line 448. Treat absence as an allowed state only when recorded. Preserve first-sidecar and creation rollback with a genuine null backup. A bounded negative should verify two unresolved attempts, no callback writes, the exact target base, the absent sidecar and the original journal.
2. **P1 — The native write callback can select a different file from the one admitted.** The downstream resolver at `storage/physical-binding.ts:153–167` uses the basename only when the JSON object lacks an `id` property. The production resolver at `packages/socket/src/services/config.ts:47–63` uses the basename for *every* non-string ID and takes its first match. In the presence of an ID-named record with a non-string ID and a valid native random-basename record, the two resolvers can disagree. The adapter passes only the logical ID to update or delete at `storage/native-recovery-adapter.ts:206,240`. Its verification runs after the callback has already modified a public file. Ensure that an ambiguous callback target blocks both writes before invoking it, or bind the write itself to the admitted file within the downstream lease. Preserve the valid case with an unrelated **string** foreign ID. A native dual-candidate regression should verify both file identities and bytes and retain the journal.
3. **P1 — Media can restore the base before discovering that it cannot restore the sidecar.** `storage/physical-binding.ts:228–317` validates the current public files and the images embedded in the journal. It checks the actual private backup file only when restoring that individual binding at lines 358–360. With both public siblings still at their legitimate detached targets, a missing or changed prepared sidecar backup passes the group check. Startup then restores the base at `media-library.ts:1264` before the sidecar fails at the next line. Immediate rollback uses the same order at lines 615–617. Preflight every private image required by the current rollback plan before the first public mutation, while allowing retries where a sibling is already fully restored. Verify that both detached siblings, the journal and the quarantine survive a failed preflight byte-for-byte.
4. **P2 — Default startup recovery can erase the ID on a native random-basename file.** Admission accepts a logical backup payload without a root ID and an on-disk base with its matching storage ID. In the `getPath`-only startup form, `storage/native-recovery-adapter.ts:207–218` writes the logical backup verbatim. For a native filename distinct from the quiz ID, the next lookup cannot rediscover that file after its embedded ID disappears. The operation has already changed it and subsequent replay remains unresolved. Preserve the admitted native storage wrapper on publication, or reject this representation before writing. Check the public default overload with a wrapper-free backup and a real native filename.
