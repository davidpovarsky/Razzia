## Backup, cutover and rollback — gated plan, not executed

`extensions/deployment/deploy-unified-site.py` is the established operator script. Before proposing execution, independently confirm the exact current production/gateway identities, candidate image ID/revision, active clients and all data writers, a private destination with restrictive permissions and sufficient space, and a **working admission/maintenance barrier with confirmed drain**. Its `last_game_count()` derives a best-effort latest count from logs; this is **not atomic admission control**, and a read-only zero-room observation does not prevent new rooms or authorize stopping clients. If atomic admission and writer quiescence cannot be established, stop before activation and ask the manager to resolve the gate. Do not infer it from health or this packet.

The script is designed to stop the original, create a private full-data archive while the application is stopped, retain the original stopped rollback container and immediately start the candidate with prior environment/mount/HostConfig. It has no independent pause for backup-integrity review before restart, and it does not establish the admission barrier or prove other writers have stopped. Those gaps require a separately reviewed guarded procedure or adjustment before executing it; this packet does not authorize one. The archive has **not** been created here.
