Canonical request fingerprint binds scope, issuer/service, phone correlation, provider reference, capability hash and explicit predecessor. Identical request retries retrieve the same receipt without minting/revealing a secret; changed fingerprints conflict. A reused provider reference with a new request is ambiguous and denied. These rules do not establish provider/PSTN identity.

SQLite BEGIN IMMEDIATE serializes predecessor CAS and request reservation. Server-registration precedence chooses one expected=0 winner; a later replacement must explicitly name the ACTIVE predecessor generation. Generation never derives from opaque reference ordering or physical chronology. Durable RESERVED/PENDING binding blocks all operations and further registrations while heap projection is uncertain. No usable ACTIVE registration exists until actual public Game admission and roster binding are observed, then the durable completion transaction commits. Rejection blocks the reserved generation; it never silently revives the prior generation. A failed projection/commit leaves durable ambiguity, with no assertion that SQL rollback undoes Game events/effects.

An injected facade consumes existing public Game methods and verifies exact game/manager/roster/client/activeCall binding. It never duplicates scoring. Every answer checks actual current epoch; no replay of pending/unknown answers. Operations durably reserve PENDING before a synchronous Game projection; completed retries return the stored receipt. Reopening does not turn pending records into executable work. A missing actual Game or changed actual binding denies without targeting a different room.
