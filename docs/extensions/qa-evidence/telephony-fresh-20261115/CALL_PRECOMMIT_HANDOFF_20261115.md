Returned metadata contains only requestId/precommitted. SQL still stores only the existing capability hash.

`register()` is explicit. It authenticates the current service/owner first, reopens/decrypts the same committed tuple, checks the independent expected call and complete immutable live binding, then invokes only the fixed typed actual registration port. No arbitrary callback with service credential and no secret getter. The port rechecks actual register authority/service ciphertext on both sides of await, snapshots input and allowlists secret-free receipt fields. Destination/host exceptions are generic, including a hostile exception echoing the per-call capability.

Lost ACK retries the same original nonce/reference/capability/predecessor, never prepare/mint/rebind. There is no local registration-permission/receipt cache. A service capability rotation can reuse an existing call tuple only when owner/game/provider/service/issuer/executor/fixed expiry/initial action ceiling are identical and the actual current service version is at least the journal version. Actual service custody must first receive and activate the new credential; the old journal never grants old-version service permission. This matches the accepted per-call server context, which does not contain credential version.

Missing/corrupt/wrong-call/wrong-key/scope files deny. A valid ciphertext under the same service/key cannot be substituted into a different expected call. Existing install marker prevents missing-file initialization or replacement preparation. Write/temp-close/unlock uncertainty poisons the instance and retains/restores a visible barrier; new instances deny. ## Host composition and deliberate remaining boundary

The existing owner-authenticated service adapter must already be explicitly configured/delivered/ACTIVE. Supply its `registrationDispatcher()` to `PrivateCallPrecommit` with `enabled:true`, a dedicated private call root/marker, gateway-purpose temporary key handle and an independently trusted expected attempt. Call prepare once, then explicitly register; use register again only to retry that same request. No raw callback object or journal creates authentication authority. The host remains responsible for authenticated provider identity/new-attempt evidence, choosing canonical phone/reference/request/predecessor and persistent key/root custody.

This slice deliberately does **not** forward poll/answer/hangup, generate/replay operation IDs, infer physical chronology or create a public/provider parser. Durable operation-intent custody and that later consumer need their own bounded contract; this registration journal must not silently create new operations on lost responses.
