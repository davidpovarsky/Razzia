# Private gateway host ports

This packet is unmounted and default OFF. The host owns real Game construction, Registry publication, the absolute private root, persistent gateway key source and trusted destination object. No environment flag, public route, provider callback parser or production gateway is added.

1. Construct `UnmountedPhoneAuthority` with existing explicit authority/lifecycle roots, `nativeAdoption: true` and `gatewayDelivery: true`. Immediately after the genuine native Game constructor, call `stageFreshGatewayGame(game)` before `Registry.addGame(game)`. Do not use an old Game removed from Registry: the host must establish actual fresh construction. The stage fence prevents native phone mutation outside the existing owning dispatch turn.
2. Use the existing manager-authenticated `initializeAuthority` and `issue`. `SecretAttempt` stays unchanged. Only the actual first secret-bearing return object obtains a weak delivery ticket; its value contains binding metadata, Game identity and control request ID. No raw credential is retained in that map.
3. `openGatewayAuthority(managerToken, {game,provider,service})` produces the scoped private host port. It retains no JWT. Every use reads the existing lease database and rechecks the actual active verified account, issuer session, lease expiry, exact native Game object and pinned executor. Its explicit action proof uses the existing request-bound verifier. Its activation calls the existing writer. It has no public/serialized form.
4. Inject that port into `PrivateGatewayAdapter`, together with `enabled:true`, an absolute canonical private root (directory mode0700), installation ID, key ID and fixed owner/game/provider/service target. Precreate only `TADAZZ_PHONE_GATEWAY_CUSTODY_V1` with exactly `private-phone-gateway-custody-v1\n` (file mode0600, one link). The adapter does not mkdir, select paths from callbacks or find/create keys. Call `initializeEmpty()` explicitly once, after the real lease exists; never as a fallback on a failed read. It leaves a permanent install marker. A missing record after installation denies.
5. `GatewayPrivateKeyPort.open()` must return a temporary owned32-byte Buffer, purpose `tadazz-phone-gateway-custody-v1`, the exact installation/key IDs and synchronous `close():void`. The adapter clears its derived key and handle Buffer on every completion and invokes close. The host must supply its persistent gateway-specific key through this private port; MCP/OAuth keys are not accepted substitutes. No key bytes or key path are stored in custody. JS credential strings are transient; this does not claim guaranteed GC zeroization.
6. `deliverGatewayAttempt(managerToken, originalAttempt, trustedDestination, expectedStoredVersion)` consumes the ticket before the first await. The trusted destination is the adapter object in this isolated packet. A future network transport must establish gateway/destination identity itself; no unauthenticated HTTP transport is provided. The sender derives the immutable binding from the real current DB, checks the actual credential hash and repeats all checks after await. Destination exceptions are replaced by generic `service_denied`. Copied attempts, metadata-only retries, stale leases and reuse after any outcome deny. No resend cache exists.
7. The receiver authenticates the live host lease before key/file access, uses authenticated AES-256-GCM with purpose-separated derived key and fixed installation/target/header binding, and atomically publishes only ciphertext. The local version is a delivery CAS only. An exact duplicate can acknowledge without overwriting; an explicit CAS can skip an undelivered version if the live authority DB agrees. An old ciphertext never grants an old permission. Failed CAS consumes the sender attempt; rotate to a new DB version for another delivery.
8. A lost ACK can leave a committed ciphertext. With the same live host and key, `inspect()` returns metadata only for the current valid binding, allowing reconciliation without retrieving/retransmitting the credential. `activate(requestId)` performs explicit real service activation; `authorization(action)` checks one explicit action and returns metadata only. It does not execute/replay registration, polling or provider operations. Neither interface exposes a secret getter or arbitrary callback with a credential.

File writes use an exclusive durable writer marker, temp ciphertext fsync, close, atomic rename and directory fsync. An uncertain write/close/rename/unlock poisons the instance and retains/restores the barrier. Fresh adapters deny when a writer marker or temp remains. A known commit followed by revocation/close denies disclosure and preserves the committed effect. No automatic unlock, missing-file initialization, custody rollback, Game/score reconstruction or compensation exists.

Runtime evidence covers a new adapter/key handle in the same real live host. A fresh OS process, host/key-store restart, independent storage failure/power loss, actual network transport and production/provider/PSTN remain unproven here. The existing authenticated SIGKILL authority-DB evidence is a separate earlier packet and does not prove gateway key custody. Later manager-owned host wiring must retain the explicit fresh Game policy; this adapter cannot reconstruct an executor from ciphertext.
