The injected context requires owner, live issuer/session identity, exact game/provider/service/executor, allowed action and expiry. A mandatory injected verifier runs before private storage/lookup, after SQLite reservation/adoption waits and on receipt replay. Missing scope denies before filesystem access. The facade pins the exact owning Game object and executor incarnation; Game loss/ownership mismatch never falls back to another room. **Fixtures establish enforcement of an injected decision only; they do not prove real account/session/service authentication, provisioning or revocation.**

One durable authority per owner/game prevents separate service/provider partitions from each replacing Game's one canonical phone index. Private queries include owner+game+provider; issuer/service/executor are pinned. A game-wide UNIQUE key blocks a competing provider authority even though its private lookup has the provider predicate. Canonical participant correlation, explicit expected-predecessor CAS, bounded transactions and durable high-water/terminal markers govern reservation. The winner is the accepted server registration; no physical chronology is inferred from opaque references, arrival time or generation.

The trusted-ingress contract is gateway-generated 256-bit capability durably precommitted with request ID and immutable scope BEFORE REGISTER. The accepted 0ad2 fixture fsynced request ID, phone, provider reference, predecessor and capability, while its separate synthetic-case.json supplied scope; those 20 results do not prove complete scoped ingress precommit. The independent review identified that gap. The subsequent fixture-only correction has its own scoped-journal results and does not change the accepted four-file server result. There is **no actual gateway journal implementation/provisioning**. Server stores a hash only, fingerprints the canonical bound request, never echoes or regenerates the capability, deduplicates matching decisions and conflicts on changed fingerprints. Raw provider-reference reuse with a new request is ambiguous and denied. Missing/corrupt proof cannot recover a registration automatically.

Reservation is durable before synchronous public Game admission. ACTIVE completion and predecessor retirement occur together only after observing actual roster/client/call identity. While RESERVED/PENDING, overlapping mutations/replacements deny. Generic admission/answer/disconnect errors remain unresolved because the actual controller/billing callback may already have caused effects. No SQL rollback claim is made about Game heap, broadcasts, billing or score. Answer epoch and current binding checks precede the canonical Game answer; stale hangup denies before invoking Game's disconnect (whose own billing finish precedes its stale check). Cached successful receipts recheck actual live binding; retired credentials get a coarse terminal result.
