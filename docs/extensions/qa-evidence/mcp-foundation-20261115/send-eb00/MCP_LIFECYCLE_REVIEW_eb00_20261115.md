## Remaining finding · cancellation during response delivery

**Source finding, scoped to transports with asynchronous delivery.** In `extensions/src/mcp-app/server/connection.ts:59–63`, completion of the registered handler sets `sdkPending=false` and releases its work count. The SDK subsequently encodes the response and awaits its transport (installed 2.4.0 server `dist/src-DdvbAHrR.mjs:6546–6561`). In `connection.ts:123–142` the wrapper translates the response to the original wire ID and awaits `inner.send`. It records no outstanding work for that await. A normal cancellation in that interval sets terminal state, clears the principal and runs `settle` (`request-boundary.ts:68–92`). With zero work and no pending SDK callback, both lookup entries can be removed although the original reply is still being sent.

The identity checks correctly prevent an old completion from deleting a successor's map entry. They cannot change the wire ID on a reply already handed to the underlying transport. The resulting gap concerns reservation of the ID and the connection's 32-slot budget during delivery. A conforming transport may resolve its public send promise asynchronously. No customer disclosure, principal substitution, or runtime delivery failure was observed. The independent runtime witness below covered ordinary overlapping delivery.

**Minimal correction.** Account for each response send, and for a still-pending related send where its parent lifetime matters, before handing the operation to the transport. Hold the owning reservation until its send promise fulfills or rejects. Keep identity-checked release in the finally path and terminal close behavior on rejection. Count the same owning operation only once if response and related parent refer to it. A short read-only transport contract test with controlled asynchronous completion should verify that a cancelled but unsettled response still occupies its slot, release occurs once after settlement, a legitimate subsequent call reauthorizes, and rejection closes only its owning connection. The guarantee ends at the transport's completion signal. Remote consumption of previously transmitted bytes is outside that signal. This change needs no SDK patch, timer, durable cache or protocol change.

## Reviewed corrections

- **Admission and cancellation.** Each factory owns its maps. Request admission reserves a slot before asynchronous verification and binds a fresh internal SDK ID to the caller's typed wire ID. Cancelled verifiers retain occupancy until their promises settle. The guard rechecks the operation after verification, so a cancelled or closed admission cannot enter a tool handler. For a forwarded tool, `run` observes the SDK's public abort signal, clears the handler-pending flag in finally, and settles the work even when the SDK suppresses a reply. The prior 14fa handler-retention finding is addressed on those paths. A started adapter operation may finish after cancellation; there is no automatic rollback.
- **Close, ID reuse and isolation.** Close marks the connection terminal and notifies the SDK before awaiting underlying close. Late authorization continuation checks connection and operation ownership before forwarding. Duplicate active wire IDs, including tool/public collisions, terminate their own connection. Producer tests cover same-ID reuse after cancelled authorization settles, a rejected send plus rejected close with sanitized errors, and a second unaffected factory. The original decoded-tool controls, strict discovery, principal checks and limiter precede tool dispatch. These lifetimes are per connection.
- **Message translation.** The SDK callback sees its internal request ID. The wrapper restores the original response ID and `TransportSendOptions.relatedRequestId` for the owning request. Progress tokens remain caller-owned values in message metadata. Non-cancellation notifications pass through; a cancellation with a known wire ID is translated to the owning SDK operation. The observed SDK uses request context `notify` to populate the related request option, separately from the progress token. Late response cleanup compares operation identity.
- **Private test ownership.** Git reports eight R100 moves from `*.test.ts` to `*.nodecheck.ts`. The private command discovers nine suites including the added lifecycle suite; intersection with parent `src/**/*.test.ts` is zero. The shared Vitest config and isolated lock are unchanged. Producer's private run executed the original 27 cases plus eight lifecycle cases, **35 passed**, with zero failures/skips/cancellations. Frozen offline install, typecheck and scoped format each exited 0. No broad parent suite was needed for the rename.
