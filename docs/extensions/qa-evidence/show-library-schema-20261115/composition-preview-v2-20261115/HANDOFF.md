# Additive composition and native preview V2 consumer handoff

This batch implements the manager-accepted explicit V2 contract. It is ready for E's renderer/Studio integration and F's existing canonical digest path. It does not establish executable Preview acceptance, a compiled renderer reference, active pins, image rights, or G readiness.

## Contract and ownership

- V1 composition parser, schema, digest meanings, repository calls, and five-argument FrameV1 producer remain available. Saved V1 documents are never upgraded automatically. `withNativePresentationV2(v1Document, nativePresentation)` creates an explicit validated copy. The new `CompositionRepositoryV2` accepts only V2 documents; both repositories use the same atomic storage implementation. The storage owner still supplies real atomic CAS/publication operations and tenant authorization.
- `CompositionDocumentV2.nativePresentation` is a versioned sidecar containing existing native stage, decoration, and overlay settings. Defaults, role settings, and per-card settings use bounded arrays and exact theme references. Source card keys remain string values, including `constructor` and lone surrogates; they are never dictionary keys or generated aliases. Stage settings merge by slot; decoration and overlays replace, including explicit empty overlay arrays.
- `prepareCompositionPreviewV2(previewDraftInput, documentInput, { draftRevision, scopeBindings? })` is host-only. It copies authored data through the existing normalizer, identity derivation, and plan resolver. Each declared composition/selection scope requires an explicit unique `{scopeId, authoredCardKey}` association to a real authored card. Identity must remain equal. The returned value carries a private brand and WeakSet association; object copies cannot mint one.
- `produceCompositionNativePreviewInputV2(prepared, snapshot, binding)` uses the genuine bound FrameV1 producer and current-card metadata. A candidate contains `inputVersion: 2`, the existing asset-free FrameV1, locale/reduced-motion, and a bounded native theme binding. The binding includes the exact bundled family reference, definition digest, document digest, all 15 effective slot variant IDs, and effective existing-schema stage/decoration values. No raw definitions, code, URLs, clocks, outcomes, or readiness authority are introduced by the sidecar.
- Unsupported custom registry sections, media URLs, image answers, active Lottie, and enabled cinematic overlays return `kind: "unavailable"`, `input: null`, and diagnostics. Every return keeps `executableAcceptance: false`. The existing host audio owner may call `resolveCompositionNativeHostThemeV2(prepared, questionId)`; it must not serialize that full resolved host theme into a renderer payload or create a second audio owner.
- Before serialization/mount, the host calls `assertCompositionNativePreviewInputV2(prepared, binding, candidate.input)`. It rejects clones and stale/mismatched question, phase, clock, draft, or plan associations. It is a host association check, not portable execution authority.
- E's payload entry imports only `native-preview-renderer-v2-schema.ts`, never the producer, normalizer, repository, digest, or root barrel. V2 admission is separate from strict V1. The payload schema validates shape/correlation; E must also resolve exact bundled definition hashes and variant IDs against its own built inputs. Prefix/shape validation alone is not an authenticity check. E owns the new renderer/build/loader admission and actual theme-switch/browser evidence. The older artifact ABI/index and empty pins remain unchanged in this batch.
- F calls `getCompositionPreviewDigestContentV2(prepared)` and feeds the exact returned full content into F's sole existing canonical digest. D adds a document-content SHA helper, not a competing MCP digest. No permissive widening of the frozen V1/0.1 path is implied.
