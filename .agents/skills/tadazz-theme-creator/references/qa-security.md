# QA and review

For each candidate record PASS, FAIL or NOT TESTED and link actual output. Cover: complete manifest, duplicate/foreign variants, uninstalled versions, unsafe URLs/paths, hashes and MIME signatures, budgets, asset rights, external Lottie resources and expressions, reduced motion; all roles and 2–5 answers; survey/multi/estimation; lock/results/tie/zero/ranking/finale; scope reset/history and JSON/native/XLSX/clone/reconnect; Chromium and WebKit viewports; no initial legacy flash/scroll; audio event tracing, restart once per epoch, ducking and autoplay recovery plus manual listening.

`ThemeInstallationStore` is the durable authority. The HTTP adapter derives principals from verified account sessions and server-assigned grants. Authoring is private to an assigned workspace; independent review is mandatory. Code-backed approval requires an exact source-controlled manifest/build record and platform grant. An uploaded hash alone grants nothing. Earlier `ThemeReviewWorkspace` is a reference, not the deployed boundary. Never expose signing keys to browsers or artifacts.

Native draft previews use short-lived, artifact-scoped media access revalidated against the live account session and workspace assignment. Published assets require manager ownership or an active room referencing the pinned approved manifest. Cache responses stay private/no-store. Publication changes future catalog availability; existing authored versions and running rooms stay pinned. Rollback selects a previously signed version without rewriting customer shows.

The CLI accepts bounded JSON and a directory of local assets. It rejects executable/archive formats instead of extracting ZIPs. Any future archive adapter must reject traversal, absolute entries, symlinks, nested archives and decompression bombs before extraction. Unsupported SVG/dotlottie archives need a dedicated reviewed sanitizer, not relaxed extension checks. Remote assets must first be imported through authorized tenant media storage; validation does not fetch them.

Code-backed candidates require platform build/review in addition to tenant approval. Declarative manifests can use only compiled renderers and bounded tokens. Content/accessibility/photoflash/licensing judgments require review; byte validation cannot prove them. Do not mark those gates green from static tests.

Run game/browser QA only on the owner-authorized remote environment in this session. The dedicated configurations reject accidental local runs. CLI `qa` runs real Chromium and WebKit preview checks, writes a private report and returns its SHA256; it does not certify manual listening, physical iPad performance or human content/licensing review. Synthetic test approval remains explicitly labeled as a fixture.
